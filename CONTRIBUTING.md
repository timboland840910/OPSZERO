# Contributing to OPSZERO

Thank you for your interest in contributing to OPSZERO! To ensure a smooth process, please follow the guidelines below:

## Code Standards
- Follow the coding style specified in the project documentation.
- Ensure that your code is well-commented and adheres to best practices.

## Pull Request Process
1. **Fork the repository** and create your branch from `main`.
2. **Make your changes** and ensure that you test your code thoroughly.
3. **Commit your changes** with clear and concise commit messages.
4. **Push your changes** to your fork and submit a pull request (PR) to the `main` branch of the original repository.
5. **Request reviews** from other contributors and respond to feedback.

## Commit Conventions
- Use the present tense and an imperative tone in commit messages. For example, "Add feature X" instead of "Added feature X".
- Each commit should include a clear and useful message describing what has been changed.
- Limit the subject line of your commit message to 50 characters, and wrap the body at 72 characters.

## Testing Requirements
- All new features and bug fixes should include appropriate test cases.
- Run all tests and ensure they pass before submitting your PR.
- Provide documentation for any new tests added.

Thank you for contributing! Your efforts help make OPSZERO better.
